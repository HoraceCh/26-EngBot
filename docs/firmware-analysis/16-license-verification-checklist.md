# 许可证与授权人工核验清单

> 建立日期：2026-07-23  
> 对应机器清单：仓库根目录 `THIRD_PARTY_COMPONENTS.json`  
> 配套资料清单：[17-materials-supplement-checklist.md](17-materials-supplement-checklist.md)  
> 说明：本文只记录许可结论、权利人授权和发布审批，不承担上游文件、版本、hash 等资料收集工作。

## 1. 使用规则

许可证任务必须以配套资料清单中的可追溯证据为输入。口头说明、文件名、仓库已经公开、代码能够编译等事实，都不能单独证明允许修改或再分发。

状态：

- `[ ]` 未完成。
- `[x]` 已完成并有证据编号、审核人和审核日期。
- `N/A` 仅可用于已从指定发布包排除的内容，并必须记录排除清单。

优先级：

- **R0——发布阻断：** 未完成时不得发布对应内容。
- **R1——条件合规：** 必须满足原许可证条件并保存证据。
- **R2——治理完善：** 影响长期可追溯性和后续维护。

## 6. 许可证据就绪判定

只有满足以下全部条件，才能将对应发布范围标记为“许可证据就绪”：

1. 本文所有适用的 R0 项已完成。
2. [资料补充清单](17-materials-supplement-checklist.md) 中对应发布范围的必需资料齐全。
3. `THIRD_PARTY_COMPONENTS.json` 中该范围不存在 `blocked` 组件。
4. 目标发布包逐文件 SBOM 不存在未知来源或未经处置的 `NOASSERTION`。
5. 发布包包含所有必须保留的许可证、版权和免责声明。
6. 发布门禁返回 `0`，并完成双人签署。

在上述条件未满足前，只能表述为“已建立许可治理和阻断机制”，不能表述为“整个仓库已经完成开源授权”。
